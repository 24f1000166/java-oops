- programs = algorithms + data structures
- traditionally algorithms come first(structured programming) and data representation comes later

-- but in object oriented design it is reverse
- first identify the data we want to maintain and manipulate and then identify algorithms to operate on the data
- debugging is easy and much easier to grasp

-- designing objects
- behaviour: what methods do we need to operate on objects
- state: how does the object react when methods are invoked?
    - state is the information in the instance variable
    - encapsulation - should not change unless a method operates on it
- identity: distinguish between different objects of the same class
    - state may be the same -- two orders may obtain the same item
- state will typically affect the behaviour, eg: cannot ship an empty order; cannot add an item to an order that has been shipped

-- relationship between classes
- dependence
- aggregation -- one class containing another class' objects
- inheritance --  one object is a specialized versions of another
